# Internacionalização (i18n)

## O que o Angular diz
Fontes: [visão geral](https://angular.dev/guide/i18n), [locale IDs](https://angular.dev/guide/i18n/locale-id), [formatar dados por locale](https://angular.dev/guide/i18n/format-data-locale), [preparar o componente](https://angular.dev/guide/i18n/prepare).
- *Locale* identifica uma região/idioma (ex.: `en-US`, `pt-BR`); define formato de datas, números, moedas e nomes.
- O locale de origem padrão é `en-US`; mude com `sourceLocale` na seção `i18n` do `angular.json`.
- Os pipes de dados (`date`, `currency`, `number`, `percent`) usam o token `LOCALE_ID`. O argumento de locale do pipe sobrescreve o global.
- Em `ng build --localize`, a CLI inclui os dados do locale e define o `LOCALE_ID`.
- A tradução é feita **em tempo de build**: um bundle por idioma (diferente de bibliotecas de tradução em tempo de execução).

## Fluxo implementado
1. **Marcar** o texto: atributo `i18n` no template, `i18n-<atributo>` para atributos e `$localize` no TypeScript. Usamos ids fixos (`@@id`) para a tradução não quebrar se o texto mudar.
2. **Extrair**: `npm run extract-i18n` gera `src/locale/messages.xlf` (idioma de origem, pt-BR).
3. **Traduzir**: `src/locale/messages.en.xlf` repete cada unidade com `<target>` em inglês.
4. **Construir**: `npm run build:i18n` gera `dist/.../browser/pt-BR` e `dist/.../browser/en`; `npm run start:en` serve a versão em inglês.

## Na página `/i18n`
Mostra: texto simples, interpolação, atributo (`i18n-placeholder`, `i18n-label`), **plural ICU** (`=0`, `=1`, `other`), `$localize` em TypeScript, o `LOCALE_ID` ativo e data/moeda no formato do idioma.

## Configuração do projeto (`angular.json`)
- `i18n.sourceLocale = "pt-BR"` e `i18n.locales.en.translation = src/locale/messages.en.xlf`.
- `polyfills: ["@angular/localize/init"]` e `types: ["@angular/localize"]` nos tsconfigs (o que `ng add @angular/localize` faria).
- Configuração `en` (`localize: ["en"]`) usada pelo `start:en`.

## O que verificamos e o que não
- Verificado no **resultado do build**: `dist/.../en` contém o texto em inglês, `locale="en"` e `<html lang="en">`; o build padrão grava `locale="pt-BR"`.
- **Não** verificado no navegador. Os testes rodam sem tradução (texto de origem).
- Os avisos "Locale data for 'pt-BR' cannot be found. Using locale data for 'pt'" são esperados: o Angular só tem dados `pt` (que é o português do Brasil).
- Só a página `/i18n` está marcada. O resto do app (menu, outras páginas) segue apenas em pt-BR. Marcar tudo é possível, mas não foi pedido.

## Consequência para o locale dos pipes
Com `sourceLocale` configurado, o build já define o `LOCALE_ID`. Por isso `provideAppLocale()` virou uma rede de segurança (só age se o build não definiu o locale) e continua necessária nos **testes**.
